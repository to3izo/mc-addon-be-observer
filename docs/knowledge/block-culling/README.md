# ブロックのカリングのルール

`RP/block_culling/<名前>.json`（`minecraft:block_culling_rules`、format_version 1.21.80）に書き、ブロックの `minecraft:geometry.culling` から参照します。

条件（condition）は次の4種類です。
- 既定（隣が「完全かつ不透明」なブロック）
- `same_block`
- `same_block_permutation`
- `same_culling_layer`（**実験的機能**。*Upcoming Creator Features* が必要なので Marketplace では使えない）

## 同じ部位に2つのルールを付けると、ファイルごと拒否される（実機で確認済み、iOS 1.26.50）

- **症状（コンテンツログ）:** `Rule 51 had geometry part 'edge_south_west' cube index -1 face index 'Unknown facing' that matches an earlier rule` のあとに `Failed to parse block culling file …` が出て、ブロック側に `Missing referenced asset <カリングの ID>` が出ます。そのブロックのカリングが**すべて**無効になります。
- 「部位」は（bone、cube、face）の組です。cube と face を省くとボーン全体を指します。ボーン全体の指定と面の指定は、同じボーンでも別の部位として扱われます（両方付けられる）。
- そのため、「隣 A **または**隣 B が X なら、この部位を消す」を1つの部位に2つのルールで書くことはできません。回避策として、ボーンに同じ形のキューブを2つ入れ、ボーン全体に A 側のルール、各キューブの面に B 側のルールを付ける方法が使えます。
- このテンプレートの `pnpm validate` は、同じ部位の重複を検出します。

## `cull_against_full_and_opaque: false` でも、不透明なブロックの隣では消える（実機で確認済み、iOS 1.26.50）

- 公式ドキュメントでは、`cull_against_full_and_opaque: false` を付けたルールは「完全かつ不透明な隣のブロック」を無視する、とされています。しかし実際には、`{ "direction": "west", "condition": "same_block", "cull_against_full_and_opaque": false }` というルールの部位が、西隣が石のときにも消えました。
- **症状:** 「同じブロックの隣でだけ消したい」装飾（枠など）が、石や土などの隣でも消えます。空中では正しく見えるので見落としやすいです。**必ず不透明なブロックの隣でも試してください。**
- **対処:**
  - カリングは、不透明な隣のブロックの裏に隠れても構わない部位（ブロック自身の面、上下のふたなど）にだけ使います。
  - 「隣が同じブロックか」で見た目を変えたい場合は、真偽値のブロック状態（`join_<面>` など）を持たせます。状態はスクリプトのカスタムコンポーネント（ブロックの `onPlace` / `onBreak`）で更新し、`bone_visibility` で表示を切り替えます。
  - 状態を増やすとパーミュテーションも増えるので、上限に注意してください（`marketplace/` 参照）。

## そのほか

- カリングとアンビエントオクルージョン（AO）は別物です。不透明なブロックの隣にある部位は、カリングで消えたのではなく、影で暗く塗られて見えなくなっている場合があります。カリングを疑う前に `block-geometry/` を確認してください。
  - 見分け方: 不透明な隣のブロックを外し、空気やガラスに替えてみます。カリングなら表示されるかされないかの二択ですが、AO は明るさが段階的に変わります。
- 状態の違う同じブロック同士もつなげたい場合は、`same_block_permutation` ではなく `same_block` を使います。`same_block_permutation` では、状態が1つでも違うと継ぎ目が出ます。

## 状態で枠を出し入れするときの規則（実機で確認済み、iOS 1.26.50 と Windows 26.52）

「同じブロックとつながっている辺では、枠を消す」ブロックを、状態で作るときの規則です（滑らかなガラスで使用）。

- 立方体の辺は、2 つの面 a と b の間にあります。**辺の枠は、「面 a の側の隣」も「面 b の側の隣」も同じブロックでないときだけ表示する**（`join_a` も `join_b` も偽のとき）。`bone_visibility` は `!q.block_state('…join_a') && !q.block_state('…join_b')` のように書く。
- この規則にすると、つなげた形の**外周だけに枠が残り**、内側の継ぎ目と、凹んだ角の辺（L 字の内側など）は枠が出ない。実機では、3×3 の壁、3×3×3 の立方体、石に埋めた窓で確認した（枠は外周だけ、石との境の辺には枠が残る）。
- 状態は、ブロック自身の `onPlace` / `onBreak` のカスタムコンポーネントで、自分と、6 方向の隣にある同じ種類のブロックについて更新する（つながる相手が同じ種類のブロックだけなので、ほかのブロックの状態は変えなくてよい）。
- 板（柱と腕）のように形が変わるブロックでは、方向ごとに `none | same | other` の 3 値を持たせる（`other` は同じ板以外。不透明なブロックにも腕を伸ばし、腕の先に枠を出す）。上下の重なりは `above` / `below` の真偽値。3⁴ × 2 × 2 = 324 パーミュテーション（`marketplace/` の上限に注意）。
- **コマンド（`/fill`、`/setblock`）で置いたときは、周囲の状態が更新されないことがある。** プレイヤーの設置・破壊で更新する作りだと、`/fill` で置き替えた板に腕がなくなる（`release-and-media/` 参照）。
