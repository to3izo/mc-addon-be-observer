# ADR-0006: 対象環境を BDS（Bedrock Dedicated Server）だけにする

- 状態: 採用
- 日付: 2026-10-18
- 決定者: 運営（利用者の指示）

## 背景
初期の計画（`docs/SPEC.md`、当時の `docs/PLAN.md`）は「通常のローカルワールドと BDS の両方」を目指していた。Phase 1 の実機確認で、ローカルワールドでは応答の回収に次の制約があると分かった（`docs/knowledge/bds-local-server/`、`docs/knowledge/device-testing-windows-vm/`）。

- クライアントのコンテンツログのファイルは、約 4 KB ずつまとめて書かれる。静かなワールドでは、応答がしばらくファイルに出てこない。
- 外部のツールが、ほかの経路で応答を受け取る方法がない。

一方、BDS では、`content-log-console-output-enabled=true` にすると、応答が標準出力に**遅れなく**出た。要求は BDS のコンソールから送れ、チートも要らなかった。

## 決定
- このアドオンは **BDS 専用**として開発する。確認と対応の表明は BDS だけで行う。
- ローカルワールド（クライアントがホストするワールド）、Realms、その他の機種は**対象外**にする。そこで動くことを妨げはしないが、確認も保証もしない。
- BDS の前提:
  - `content-log-console-output-enabled=true`（スクリプトの `console.*` を標準出力に出すため）
  - 要求の送り方は 2 つ
    - BDS のコンソールから（チート不要）
    - オペレーターのプレイヤーのチャットから（チートと operator が必要）
  - 応答の回収は、BDS の標準出力を読む外部のしくみで行う。参考の実装は `docs/knowledge/bds-local-server/scripts/bds-console-bridge.ps1`。

## 理由・検討した案
- 利用者の目的（外部の AI 操作ツールによるプレイ）では、サーバーを用意できる。BDS なら、標準出力と標準入力という、機械向けの経路がそろう。
- ローカルワールドも残す案は採らなかった。応答の回収が遅れることがあり、確認の手間に見合わない。
- コアの API の方針は変えない。安定版 `@minecraft/server` だけを使う（ADR-0001）。BDS 専用でも、ベータ版のモジュールには、ワールドで実験的機能を有効にする必要がある。そのため、ADR-0004（通信アダプターの分離）の理由のうち「ベータ版・実験的機能」は残る。一方、「通常ワールドで動かなくなる」は理由でなくなった。

## 影響
- `docs/SPEC.md`（対応環境）、`docs/PROTOCOL.md`（送受信の前提）、`docs/TESTING.md`（環境のケース）、`docs/ROADMAP.md`、`SECURITY.md` を BDS 前提に直す。
- ADR-0004 は保留のまま。採否を決めるときは、BDS 専用であることを前提に考え直す。
- Marketplace に出すことは、事実上考えない（Marketplace はクライアント向けの配布）。ADR-0002 の「1.0.0 = Marketplace 公開」は、最初のリリースの前に決め直す（ADR-0002 の経過）。

## 経過
- 2026-10-18: Phase 1 のゲーム内の確認中に、利用者が「BDS でしか利用できないものとして開発する」と指示した。ローカルワールドで得た結果は参考として残す（`docs/TESTING.md` の記録、ナレッジ）。
