# ADR-0002: バージョン番号の付け方

- 状態: 採用（テンプレートの出発点。アドオンごとに見直す）
- 日付: （このアドオンを作った日に書き換える）
- 決定者: 運営

## 背景
実機の確認用ビルドを何度も作る（iPhone は、UUID とバージョンが同じパックを取り込まない）。公開版をどう番号付けするかを、先に決めておく。

## 決定
- **メジャーは、公式マーケットプレイスに公開するまで 0 のまま**（公開時に 1.0.0）。
- **仕様を変えたらマイナーを上げる**（機能の追加、バニラとの違いの変更、挙動の変更）。
- **それ以外はパッチを上げる**（修正、見た目の調整、文書、アイコン、翻訳）。実機の確認用ビルドごとにも、パッチを上げる。
- 全体で 1 つのバージョンを、`pnpm version:set` で、`package.json` とパックのマニフェストに一括で設定する（`AGENTS.md` の Version policy）。

## 理由・検討した案
- 公開前に 1.0.0 を名乗ると、公開版との区別がつかなくなる。公開（Marketplace への提出）が、1.0.0 の意味になる。
- ワールドが参照するもの（ブロックの状態、識別子）を変えるときは、`AGENTS.md` の方針（世界に互換性のない変更はメジャー）に当たる。0.x のうちは、マイナーを上げて、CHANGELOG に書く。

## 影響
- `CHANGELOG.md`、`package.json`、両パックの `manifest.json`、`AGENTS.md`。
- 確認用ビルドの変更は、最初の公開版の CHANGELOG にまとめて書く（`docs/knowledge/release-and-media/`）。
