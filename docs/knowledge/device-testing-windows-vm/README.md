# Windows 11 VM（VMPal）での確認

macOS 上の VMPal の Windows 11 VM で、Minecraft Bedrock（Windows 版）を操作して確認したときの手順と落とし穴です。すべて実機（VM）で確認済みです（2026-10、タイトル画面の表示 v26.52）。

## ビルドを入れる

- `pnpm build` で作った `dist/<slug>_BP` と `dist/<slug>_RP` のフォルダを、VMPal でデスクトップに送り、PowerShell で次の場所へコピーする（`.mcaddon` のインポートより速く、開発用パックなので同じバージョンでも上書きされる）。
  - `%APPDATA%\Minecraft Bedrock\Users\Shared\games\com.mojang\development_behavior_packs\<slug>_BP`
  - `%APPDATA%\Minecraft Bedrock\Users\Shared\games\com.mojang\development_resource_packs\<slug>_RP`
- 更新するときは、先にデスクトップの古いフォルダを消してから送る（同名があると送り先が混ざる）。コピーしたあと、ワールドを「セーブして終了」で抜けて入り直すと、パックが読み直される。ゲームの再起動は要らなかった。
- 新規ワールドでは、「ビヘイビアーパック → 利用可能」から自分のパックを有効にする。リソースパックは依存関係で一緒に有効になる。実験的機能はすべてオフのままにする。

## エラーを読む

- 「設定 → クリエイター」にある「コンテンツ ログの履歴」の「表示」から、`[Actor][error]` などの全文を読める。テストの前に「クリア」を押すと、古いログと混ざらない。
- ログファイル（`%APPDATA%\Minecraft Bedrock\logs\ContentLog*.txt`）は、ゲームが動いている間は空のことがあった。画面で読むほうが確実。

## 「開かない」ときに疑うこと（実機で確認済み）

- **サバイバルでは、クリエイティブより届く距離が短い。** クリエイティブで開けた位置（チェストの 5 ブロックほど手前）から、サバイバルで右クリックしても、何も起きなかった（ログにもエラーは出ない）。エンティティへの右クリックは、サバイバルのほうが短い距離でしか届かない。**確認のときは、クリエイティブに切り替える（`/gamemode creative`）か、サバイバルで近づく。** 「前のビルドでは開いたのに開かない」ときは、ゲームモードと距離を、先に確認する。
- ポーズメニューを出すための Esc が、1 回で反応しないことがある。メニューが出ていないのに「セーブして終了」の座標をクリックすると、ゲーム内のクリック（視点の回転やブロックの使用）になる。クリックの前に、スクリーンショットで、メニューが出ていることを確認する。
- 新しいビルドを入れたら、**ワールドを抜けて入り直す**（上の手順）。ファイルをコピーしただけでは、動いているワールドのスクリプトは入れ替わらない。

## 操作の落とし穴（VMPal の MCP 経由）

- キーボード配列が日本語（JIS）なので、`type` での文字入力は US 配列として解釈されて化ける。`key` で物理キーを送る。例: `_` は `shift+IntlRo`、`:` は `Quote`、`@` は `BracketLeft`、`/` は `Slash`、`-` は `Minus`。チャットに `/scriptevent to3izo_sec:status` と入れるには `Slash s c r i p t e v e n t space t o 3 i z o shift+IntlRo s e c Quote s t a t u s Enter`。
- チャット画面を閉じるには、Esc を **2 回**押す（1 回目は入力欄のフォーカスが外れるだけ）。左上の「戻る」は、押しても閉じないことがあった。チャットを開いたまま `4` などを押すと、チャットの文字として入力されてしまう。
- コマンドを実行するとチャット画面が閉じる。続けて打つ前に `t` で開き直し、2 秒ほど待つ。待たないと文字が落ちる。
- ゲーム内のクリックは、`mouse_move` のあとに 0.5 秒待ってから `left_click` を送る。続けて送ると、1 回目が無視されることがあった。
- スクリーンショットは 1 コマ遅れることがある。操作のあとは 2〜3 秒待ってから撮る。
- スクリーンショットの `maxWidth` を変えると、その幅が以降の座標系になる（450 を指定すると 450×234 になった）。座標で操作する前に、`maxWidth` 900 で撮り直して揃える。
- 連打は `act` に `left_click`（座標は画面の中心）と短い `wait` を並べる（`settle: false`）。1 回の呼び出しに 50 アクションまで。長押しは `mouse_button` の `down` と `up`。
- 画面の座標系は、直前のスクリーンショットの幅に合わせて変わることがある（900×468 になった）。クリックの座標は、最後のスクリーンショットの値で指定する。
- ゲームがマウスを掴んでいるとき、`mouse_move` は視点の回転になる（中心からの差分）。回転量は、画面上の移動の約 2.4 倍になった。狙った所をクロスヘアに合わせるには、数回に分けて確かめる。
- HUD（ホットバーなど）が映らない状態だった。ホットバーはインベントリ（`E`）を開くと見える。
- `/tp <名前> x y z facing x y z` で、位置と向きを決められる。視点合わせより確実。

## 2 人での確認（VM をホストにして iPhone が LAN で参加。2026-10-12）

- VM のネットワークを `vmpal_update_vm` で `bridged`（Mac の主なインターフェース、例 en0）にする。Windows は再起動なしで切り替わり、VM が iPhone と同じネットワークのアドレス（例 <VM の LAN 側のアドレス>）を持つ。共有（NAT）のままでは iPhone の LAN 一覧に出ない。
- ワールドは新しく作る（前のワールドは、パックのバージョンが違うと読み込まれない）。ゲームモードはクリエイティブにすると、チートが無効になる。設定の「ゲーム」の一番下にある「チートの実行」をオンにする（右のスクロールバーをドラッグすると速い。マウスホイールは遅い）。
- 「マルチプレイヤー ゲーム」と「LAN プレイヤーに表示」は、新規ワールドで初めからオン。iPhone の「プレイ」→「フレンド」の LAN に出る。出なければ、「サーバー」でアドレスとポート 19132 を指定する。
- 同じアカウントは、同じワールドに二重に入れない。iPhone は別の Microsoft アカウントでサインインする（iOS のゲームは Apple ID で購入したものが使える）。サインインなしでは、サーバーやフレンドの欄に入れない。
- HUD（アクションバーなど）は、`F1` で表示される。非表示のままだと、使用中のメッセージが画面に映らない。
- `/give` などのコマンドは、チートがオフだと使えない。`/setblock ~ ~ ~3 to3izo_sec:shared_ender_chest` のように、チェストを置ける（JIS 配列で `~` は `shift+Equal`、`=` は `shift+Minus`）。

## 強制終了と再起動（F-sec-14。2026-10-12）

- ゲームの強制終了は、VM の `vmpal_exec` で `Get-Process | Where-Object ProcessName -like 'Minecraft*' | Stop-Process -Force`。操作の直後に止めたいときは、先に待機つきのジョブ（`Start-Sleep 13; …`、`waitSeconds: 0`）を起動してから、画面操作を始める。
- 再起動は `explorer.exe shell:AppsFolder\Microsoft.MinecraftUWP_8wekyb3d8bbwe!Game`（`explorer.exe` は終了コード 1 を返すが、ゲームは起動する）。
- コンテンツログのファイル（`ContentLog*.txt`）は、ゲームが動いている間は 0 バイトのままだった。「設定 → クリエイター → コンテンツ ログの履歴 → 表示」で読む（GUI ログのレベルは「警告」）。`console.warn` の行もここに出る。
- 設定画面のスクロールは、マウスホイールだと遅い。スクロールバーのつまみをドラッグすると速い。

## アイテムを出す方法（2026-10-12）

- クリエイティブの画面で、グループ（花火、ポーションなど）の中から選んでホットバーに入れる操作は、遅くて不安定だった。チートをオンにして、チャットの `/give @s <アイテム> <個数> <データ値>` で出すほうが確実（`potion 1 12` = 耐火のポーション、`bundle`、`writable_book`、`enchanted_golden_apple`、`diamond 5`）。チャットは `t` で開き、3 秒待ってから入力し、1 秒待って Return を押す。続けて入力するときは、そのたびに `t` から始める。
- バンドルに入れるには、クリエイティブの画面でホットバーのアイテムをクリックして持ち、バンドルをクリックする。
- ゲームを長く動かすと、VM の画面が止まり、`vmpal_exec` も応答しなくなったことがあった（`vmpal_restart_vm` の `restart` でゲストが再起動し、ロック画面に戻った）。再起動後のサインインは、パスワード入力が必要なので人が行う。VMPal の「自動でサインイン」をオンにすると不要になる。

## `.mcaddon` で入れる場合と、補助パックの置き方（Windows 26.52、2026-10-11。実機で確認済み）

- **起動中のゲームに `.mcaddon` を開かせても、取り込まれなかった。** 設定画面を開いたままダブルクリックしても、何も起きない（エラーもない）。**ゲームを終了してから**デスクトップの `.mcaddon` をダブルクリックすると、ゲームが起動して取り込まれた。
- 取り込み先は `%APPDATA%\Minecraft Bedrock\Users\Shared\games\com.mojang\behavior_packs\<フォルダ名>` と `resource_packs\…`（フォルダ名はパック名を縮めたもの。`Smooth Glass` は `SmoothGlas`）。`manifest.json` の `version` で、取り込まれたバージョンを確かめる。
- ワールドに有効にしたパックは、**ワールドのフォルダ（`minecraftWorlds\<ID>\behavior_packs\`）にもコピーされる**。`world_behavior_packs.json` を手で書き換えても、ワールドを開くと元に戻っていた。パックは画面から有効にする（ワールドの編集 → ビヘイビアーパック → 利用可能 → 有効にする。「ワールドを更新しますか？」は「それでもパックを追加する」）。
- ワールドのフォルダ名は `RsnnT2s0Np0=` のような ID。PowerShell の表形式（`Format-Table`）では、長いパスが `...` と省略されるので、`Name` や `FullName` を 1 行ずつ表示する。

## 撮影・テスト用の `.mcfunction`（補助パック。実機で確認済み）

- 足場やテスト用の配置を毎回打つのは大変なので、`functions/*.mcfunction` だけを入れた補助パック（BP、`manifest.json` と `data` モジュールのみ）を作り、ワールドに有効にすると、`/function <名前>` で一括実行できる。補助パックはアドオンのリポジトリには入れない（`/tmp` などに置く）。
- **追加・変更した `.mcfunction` は、ワールドを「セーブして終了」で抜けて入り直すと確実に読み込まれた。** `/reload` だけでは「関数 〇〇 が見つかりません」のままのことがあった。
- **関数が「見つかりません」と出るのは、ファイルがないときだけではない。** 中のコマンドに 1 行でも解析できないものがあると、関数ごと読み込まれず、`/function` では「見つかりません」と出る（原因は、ログ履歴に `[Commands][warning]-Function … failed to load correctly` と、行番号つきで出る）。
  - 実際に起きた例: `beetroots`（正しくは `beetroot`）、`oak_pressure_plate`（このバージョンでは解析できなかった）。エンティティは `tropical_fish` ではなく **`tropicalfish`**。ブロックの状態の書き方は `farmland` や `wheat ["growth"=7]`。
  - 対処: 関数を作る前に、ゲーム内のチャットで同じコマンドを 1 回打って、通るか確かめる。
- JIS 配列の日本語キーボードで、座標つきのコマンドを打つ文字列は、スクリプトで作ると楽（`_` → `shift+IntlRo`、`:` → `Quote`、`@` → `BracketLeft`、`[` → `BracketRight`、`]` → `Backslash`、`~` → `shift+Equal`、`=` → `shift+Minus`）。チャットは、`/` を押してから **1.5〜2 秒待って**、続きを打つ。待たないと、先頭の文字が落ちる（`/weather` が `ather` になった）。
- **ゲームの画面が外れているときの F1 に注意。** ゲームの画面がフォーカスを失った状態（デスクトップなど）で F1 を押すと、Windows のヘルプ（Edge）が開き、続けて打ったコマンドが Edge の検索欄に入る。コマンドを打つ前に、スクリーンショットでゲームの画面が出ていることを確かめる。

## 画面の大きさと、保存される画像（実機で確認済み）

- VMPal の `vmpal_window` の `fullScreen` で、ゲストの画面が **1920×1080** になった（ウィンドウのままだと 1920×998）。このとき `vmpal_screenshot` の座標系は、既定の `maxWidth` で 1280×720 になる。
- ゲーム内の **F2** は、`%APPDATA%\Minecraft Bedrock\Users\<ID>\games\com.mojang\Screenshots\<数字>\<UUID>.jpeg` に、jpeg で保存される。**解像度は画面と同じ 1920×1080、HUD は F1 で消せば写らず、Windows のライセンス認証の透かしも入らない**（透かしはゲームの描画の外にあるため）。保存まで 2〜3 秒かかる。直後に取りにいくと、前の画像を拾う。
- 設定画面やインベントリなど、F2 で撮れない画面は、ゲストのウィンドウだけを PowerShell で保存する（`PrintWindow`）。`Minecraft.Windows` のウィンドウを `EnumWindows` で見つけ、`PrintWindow(hwnd, dc, 2)` で描画し、`GetClientRect` と `ClientToScreen` で枠を除いて切り抜くと、**透かしなしの 1920×1080** が得られた（`CopyFromScreen` は透かしごと写る）。`vmpal --cli cp` で Mac に取り出す。
- `vmpal` コマンドは PATH になくても、`/Applications/VMPal.app/Contents/Helpers/VMPalMachine.app/Contents/MacOS/VMPalMachine --cli cp|exec …` で使える（`cp "<VM名>:AppData\Roaming\…\." ./out/`、フォルダの中身は末尾を `/.`）。

## ゲームが応答しなくなったとき（実機で確認済み）

- 配置コマンドや `/camera`、F2 を多用した後、Minecraft が「応答していません」のまま、約 10 分戻らなかった（CPU は動いていた）。ログにアドオン由来のエラーはない。`Stop-Process -Name Minecraft.Windows -Force` で止め、`cmd.exe /c start "" minecraft:` で再起動できた（ほかのヘルパーのプロセスは残るが、問題なし）。再現条件は不明。
- **強制終了は、人の了承を得てから行う。** VM を別のセッションが使っていることがある。

## チャットへの長い文字列の入力と、コンテンツログのファイル（実機で確認済み、2026-10-18、Windows 1.26.52.3）

- **クリップボードから貼り付けると、JIS 配列の問題を避けられる。** `vmpal_exec` で `powershell.exe -STA -Command "Set-Clipboard -Value '<文字列>'"` を実行し、ゲームで `t` → 2.5 秒待つ → `ctrl+v` → `Return`。`"`・`{`・`}`・日本語を含む `/scriptevent` も、そのまま入った。`vmpal_act` の `type` は、JIS 配列では止められる（US 配列として打つため）。日本語を PowerShell の引数に直接書くと化けることがあるので、`[char]0x30C6` のように組み立てる。
- **長いコマンドで切断される。** チャットから 511 文字以上の `/scriptevent` を送ると、そのプレイヤーが切断された（ローカルワールドでは「ホストから切断されました」`ClientDisconnection-41`・「Bat」、BDS では「マルチプレイ接続失敗」`ClientDisconnection-122`・「NetherNet」）。448 文字までは通った。切断のあと、ワールドに入り直せば続けられる。
- **コンテンツログのファイル（`%APPDATA%\Minecraft Bedrock\logs\ContentLog*.txt`）は、ゲームの動作中も書かれるが、約 4 KB ずつまとめて書かれる。** ログの出力が少ないと、直前の行がしばらくファイルに出てこない（ワールドを抜けても出ないことがあった）。ファイルはゲームが開いたままなので、`[IO.File]::Open(path, 'Open', 'Read', 'ReadWrite')` で共有モードで読む。ファイルのログの水準は verbose で、`console.log` は `[Scripting][inform]`、`console.warn` は `[Scripting][warning]` として出た。以前の「動作中は 0 バイト」という記録と違うので、バージョンや条件で変わる可能性がある。
- エラーの詳細（「詳細表示」）に、`Version: 1.26.52-Windows GDK Build`、`Transport: NetherNet:2193` が出た。ローカルワールドへの接続も NetherNet で、プロトコルの版は 2193。
