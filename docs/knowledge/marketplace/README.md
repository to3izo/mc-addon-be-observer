# Marketplace

出典: 「Guidelines for Building Cooperative Add-Ons」（learn.microsoft.com/minecraft/creator、Documents → Practices）。2026-10 時点で確認。

## 協調型アドオンの必須要件（公式資料）

- **実験的機能を使わない。** ガイドラインに「Add-Ons should not use or rely on Experimental features.」とあります。*Upcoming Creator Features* などの実験トグルが必要と書かれている機能は使えません。実験的機能を有効にしたワールドは実績が解除されず、後からオフにもできないので、プレイヤーにとっても不利です。
- **追加のみ。** バニラのブロック・アイテム・エンティティ・レシピ・テクスチャ・音・UI・フォント・`.lang` の文字列を上書きしたり変えたりしない。スクリプトでバニラの遊び方を変えない。アドオンを外してもバニラの遊びが壊れないこと。
  - 結果として（推測）、「バニラの X を置いたら改良版の X に差し替える」設計は使えません。新しいブロックやアイテムとして追加し、入手を簡単にします（例: 石切台でバニラと相互変換できるレシピ）。
- **提出できるのは Marketplace パートナー**（Minecraft Partner Program の加入者）だけです。
- **パックの構成:** BP と RP を1つずつ。両者が UUID でお互いを依存先にする。RP のヘッダーに `"pack_scope": "world"`。両方に `min_engine_version`。（このテンプレートでは `pnpm init:addon` がすべて書き込み、`pnpm validate --strict` が確認します。）
- **命名:** 名前空間はアドオンごとに固有の `<作者名>_<パック略称>`。テクスチャの名前、モデル（`geometry.<名前空間>.<名前>`）、カリングルール、音、言語ファイルのキー、タグにも名前空間を付ける。ファイルは `textures|sounds|loot_tables|functions|trading/<作者名>/<パック名>/` に置く。
- **サイズと性能:** 25 MB 未満、ファイル 3,500 個未満。**ブロックのパーミュテーションは合計 1 万未満**。ブロックとアイテムのテクスチャは 256×256 以下。ティッキングエリアを使わない。

## 出品までの道（2026-10 時点で調査。公式ページで確認できたもの以外は推測）

- **前提（公式資料）:** 販売できるのは Minecraft Partner Program の加入者だけ。個人がそのまま申請して出品する仕組みはない。
- **A. 自分でパートナーになる。** 申請先は https://www.minecraft.net/en-us/partner 。
  - 公式ページに書かれている条件（公式資料）:
    - 高品質で独自のコンテンツをコミュニティに公開してきた実績（マップ、スキン、テクスチャ、アドオンなどのポートフォリオ）
    - 事業として運営する姿勢。キーアート・スクリーンショット・トレーラー・説明文を用意できること（申請時にも必要）
  - 推測（第三者の情報。公式ページでは未確認）:
    - 法人など登録された事業者であること
    - 18 歳以上
    - 申請書で事業と税務の情報を出す
    - 審査は数週間〜数か月
  - 日本の個人事業主が「登録された事業者」に当たるかは未確認。申請前に公式に確認すること。
- **B. 既存のパートナーに出版してもらう（推測。条件は各社と相談）。** 個人クリエイターの作品を代わりに出版する窓口を持つパートナー企業がある（例: Noxcrew、Waypoint Studios、Pathway Studios）。事業者登録なしで出せる可能性がある代わりに、売上はパートナーと分ける。
- **混同注意（公式資料）:** 2026 年に始まった Minecraft のアフィリエイトプログラム（https://www.minecraft.net/en-us/affiliates）は、Marketplace の商品を紹介して報酬を得る別の仕組みで、出品には使えない。
- **準備物:** 規約に沿って作った `.mcaddon`、`media/` のキーアート・スクリーンショット・トレーラー・説明文、（A なら）実績になる公開作品。

## 価格の目安（推測。第三者の集計による、2026 年時点）

- 有料コンテンツの中央値は約 310 コイン、約 6 割が 320 コイン以下。人気の大型アドオンは 800〜1,700 コインが多い。
- 1 コインは約 1 米セントで、購入単位・地域・機種で変わる。「1 コイン = 1 円」ではない（日本円では 1〜1.5 円前後）。
- 小〜中規模の見た目を良くする系のアドオン（例: 36 ブロックの滑らかなガラス）なら、160〜310 コインが相場の範囲。最終的な価格はパートナー（または出版元）との取り決めに従う。

## パーミュテーションの見積もり（ガイドラインと、Bedrock のブロック登録の仕組みからの推測）

ブロックの状態の値の組み合わせは、コードで使うかどうかに関係なく、すべてパーミュテーションになります。

`パーミュテーション数 = Π（各状態の値の数）`。これを全ブロックで合計します。

- 真偽値 4 つで 16、6 つで 64、3 値の列挙を 4 方向に持つと 81。
- 色や素材のバリエーション数を掛けます。18 種類 × 256 = 4,608。
- 状態を設計する**前に**計算してください。滑らかなガラスの板ガラスでは、上下の重なりを腕ごとに正確に扱うと 1 方向あたり 6 値が必要でした。6⁴ = 1 種類 1,296 × 18 色 = 23,328 となり上限を超えるため、簡略化したモデル（3⁴ × 2 × 2 = 1 種類 324）を選び、制限事項として記録しました。
- `vanilla-reference/scripts/count-block-permutations.mjs` で、ビヘイビアパックの合計を出せます。

## バニラのテクスチャを使う（推測。リリース前に Marketplace の窓口で確認すること）

- Mojang のテクスチャファイルをパックに**コピーしない**でください。再配布にあたり、審査で問題になるおそれがあります。
  - **このプロジェクトの現状（2026-10-12）**: owner の判断で、バニラの参考画像の画素データから起こした、スカイブルーの色替えのテクスチャを使っている（ADR-0005）。提出前に、描き起こし版に戻すか、窓口に確認する。
- **名前での参照なら、ガイドラインの範囲では問題ありません。** カスタムブロックのマテリアルに、バニラの地形テクスチャのキーをそのまま指定できます（`"texture": "glass"`、`"red_stained_glass"`、`"glass_pane_top"`）。ファイルは同梱されず、バニラも上書きしません。プレイヤーが使っているリソースパックにも追従します。
- ただし、参照してよいと明記した公式の文書はありません。ガイドラインが禁止しているのは上書きだけです。パートナーになったら Marketplace の担当に確認してください。
- バニラのブロックとそっくりなブロックは、インベントリでプレイヤーが混同しやすくなります。名前で区別をつけ、クリエイティブでの並び順も整えます（`block-definitions/` 参照）。

## カスタムブロックの上にモブが湧く（2026-10-14 に利用者から報告。実機の確認は未実施）

- **報告:** ゴーレムトラップで、沸き層の周りの壁に滑らかなガラスを使ったところ、水流源に隣接したガラスの上面に、アイアンゴーレムが湧いた。
- **バニラのガラスでも起きる可能性がある（公式資料）。** [Minecraft Wiki のアイアンゴーレム](https://minecraft.wiki/w/Iron_Golems)は、Bedrock では「上面が完全なブロック（ガラスを含む）で、上に障害物がなければ湧く」と書いている。バージョンで変わっており（[MCPE-140244](https://bugs.mojang.com/browse/MCPE-140244)、Java の [MC-262340](https://bugs.mojang.com/browse/MC-262340)）、使うバージョンで確かめる必要がある。
- **ブロックの定義に、モブのスポーンを禁止する設定は見つけられなかった**（公式の「Block Components List」を全部は読んでいないため、推測）。
- **`minecraft:spawns_on_block_prevented_filter` は、ブロックでなく、モブ側の設定。** `BP/spawn_rules/<モブ名>.json` の `conditions` に、「そのモブが湧かないブロック」の識別子の配列を書く（[Bedrock Wiki: Spawn Rules](https://wiki.bedrock.dev/entities/spawn-rules.html)）。バニラのモブに書くには、バニラのスポーンルール（`minecraft` の名前空間）を上書きすることになり、**協調型アドオンのガイドラインに反する**。自作のモブにだけなら、使える。
- アイアンゴーレムは、村のロジックでスポーンするため、スポーンルールを書き換えても効かない可能性がある（推測）。
- **当たり判定の高さを、ほんの少し（例: 15.9/16）低くして、「上面が完全なブロック」でなくす案**を検討した。効くかは未検証で、松明などの置ける条件に影響するおそれがある。**採用しなかった。**
- **判断（このプロジェクト）:** 回避策は入れず、**紹介ページの注意事項に「モブが湧くことがある」と書く。** 同時に、モンスタートラップの床や壁に使える、という使い道として紹介する。バニラのガラスが同じ条件で湧くかは、確認するまで断定しない（確認の手順は、テスト計画に入れておく）。
