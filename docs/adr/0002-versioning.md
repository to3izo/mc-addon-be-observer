# ADR-0002: バージョン番号の付け方

- 状態: 置き換え済み（ADR-0013）
- 日付: 2026-10-18
- 決定者: 運営

## 背景
実機の確認用ビルドを何度も作る（iPhone は、UUID とバージョンが同じパックを取り込まない）。公開版をどう番号付けするかを、先に決めておく。

## 決定
- **1.0.0 は、外部の人が使える最初の公開版**とする。条件は、README の手順で導入して使えること、プロトコルが確定していること（protocol 1）、リリース前のチェックリストを BDS で通したこと。Marketplace への公開は、このアドオンの節目にしない（BDS 専用。ADR-0006）。
- 1.0.0 のあとは、**互換でない変更でメジャーを上げる**: プロトコルの互換でない変更（`protocol` の番号を上げる変更）、ワールドとの互換性を壊す変更、対応環境を狭める変更。
- **仕様を変えたらマイナーを上げる**（メソッド・項目・引数の追加など、互換な機能の追加と挙動の変更）。
- **それ以外はパッチを上げる**（修正、見た目の調整、文書、アイコン、翻訳）。実機の確認用ビルドごとにも、パッチを上げる。
- 全体で 1 つのバージョンを、`pnpm version:set` で、`package.json` とパックのマニフェストに一括で設定する（`AGENTS.md` の Version policy）。

## 理由・検討した案
- このアドオンの利用者は、外部のツールの作者で、頼りにするのはプロトコルと導入の手順である。そのため、1.0.0 の意味は「外部で使える状態になった」とし、メジャーは「ツールの側の修正が要る変更」で上げる。
- もとの「1.0.0 = Marketplace 公開」は採らなかった。BDS 専用にしたので、Marketplace（クライアント向けの配布）に出す予定がなく、メジャーが 0 のまま止まってしまう。
- ワールドが参照するもの（識別子など）を変えるときは、`AGENTS.md` の方針（ワールドと互換でない変更はメジャー）に当たる。

## 影響
- `CHANGELOG.md`、`package.json`、両パックの `manifest.json`、`AGENTS.md`。
- 確認用ビルドの変更は、最初の公開版の CHANGELOG にまとめて書く。

## 経過
- 2026-10-18: Bedrock Observer の初期設定で見直し、このアドオンでも採用した。アドオンのバージョン（`package.json`・マニフェスト）と、公開プロトコルのバージョン（応答の `protocol`）は別に管理する（ADR-0003）。このアドオンは GitHub での OSS 公開が主で、Marketplace に出すかは未定。「1.0.0 = Marketplace 公開」のままにするか、「1.0.0 = 最初の安定した OSS リリース」に読み替えるかは、最初のリリースの前に決め直す（承認待ち）。
- 2026-10-18: 対象を BDS だけにした（ADR-0006）。Marketplace はクライアント向けの配布なので、「1.0.0 = Marketplace 公開」は当てはまりにくい。決め直しは、引き続き最初のリリースの前に行う。
- 2026-10-18: 初回リリースの前に決め直した。利用者の判断で、「1.0.0 = このアドオンを外部で使える状態」にした（上の決定）。最初の公開版を 1.0.0 にする。
- 2026-10-18: 利用者の指示で、SemVer をもとにした方針（ADR-0013）に置き換えた。
