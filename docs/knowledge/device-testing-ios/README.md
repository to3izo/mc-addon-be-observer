# iPhone / iPad での確認

すべて iOS 版 Minecraft 1.26.50（2026-10）で確認済みです。手順の一覧は `docs/TESTING.md` を見てください。

## ビルドと転送

- `.mcaddon` を書き出すのは `pnpm package` です（`pnpm build` ではない）。`dist/<slug>-<version>.mcaddon` に出力されます。`pnpm build` は最初に `dist/` を空にします。
- 送るのは `.mcaddon` だけで足ります（両パックが入っている）。
- AirDrop は **Finder から**送ります。「ファイル」アプリの *Minecraft* フォルダには入れないでください。Minecraft はそこにある `.mcaddon` を読み込みません。「共有」→「Minecraft」で開きます。

## 「新しいビルドを入れたのに古いまま」の落とし穴

1. **UUID とバージョンが同じパックは、取り込みが飛ばされます。** Minecraft は何も言わずに、入っているパックを使い続けます。
   - 対処: 端末に入れるビルドごとにパッチ番号を上げる（`pnpm version:set 0.1.x`）か、先に「設定 → ストレージ」で古いパックを削除する。
2. **「ファイル」の「最近の項目」に古いコピーが出ます。** iCloud Drive や「最近削除した項目」の中のファイルも並びます。同じ名前のファイルを「最近の項目」から選んで、古いビルドを何度も取り込んでしまいました。
   - 対処: ファイル名にバージョンを入れる（このテンプレートの `pnpm package` はそうしている）。開くときは「最近の項目」からではなく、バージョンで検索する。古いコピーは「最近削除した項目」の中も含めて消す。
3. **取り込まれたバージョンを確かめる:**
   - 「設定 → ストレージ → ビヘイビアパック / リソースパック → 管理」にバージョンが表示される。
   - または「ファイル」で `Minecraft → games → com.mojang → behavior_packs → <パック> → manifest.json` を開く。
4. 古いビルドで置いたブロックは、古い状態のままです。状態を変えたあとは、置き直すか新しいワールドで確認してください。

## ワールドへの適用

- ワールド一覧 → 鉛筆アイコン（*編集*）→ *ビヘイビアパック* で *使用中* を確認する。
  - なければ *利用可能* から探す。iPhone では *購入済み* の中にある場合がある。
  - 有効にすると、RP は依存関係で一緒に有効になる（*リソースパック → 使用中* で確認）。
- アドオン自体にチートは不要です。テスト用のワールドでは、`/gamemode` や `/give` を使うためにオンにしておくと便利です。

## エラーの読み方

- コンテンツログは「設定 → クリエイター → コンテンツログの GUI」で有効にします。ゲーム中のログ履歴には **コピー** があるので、報告するときは全文を貼ってください。
- テストの前に **クリア** を押しておくと、古いログを新しいものと取り違えずに済みます。
- ゲーム中にコンテンツログを表示・出力するコマンドはありません。履歴は「設定 → クリエイター → コンテンツログの履歴」から開けます。

## 新規ワールドの初回だけ出る「読み込みに失敗しました」（実機で確認済み、iOS 1.26.50）

- **症状:** 新規ワールドに初めて入ったときだけ、「いずれかのリソースパックまたはビヘイビアーパックの読み込みに失敗しました。」と表示される。2回目以降は出ない。
- **原因:** 自作のアドオンではない。アドオンを何も適用しない新規ワールドでも同じように表示された。iPhone 版に最初から入っている、共有の新しいパックが原因と見られる（どのパックかまでは特定していない）。
- **対処:** 自作のアドオンの不具合と取り違えないこと。同じ表示が出たら、まずアドオンなしの新規ワールドで出るかを確かめる。

## バニラとの比べ方

- すべてのテストを、**空中**と**不透明なブロックの隣**（石の窓など）の両方で行ってください。描画の問題（カリング、アンビエントオクルージョン）には、不透明なブロックの隣でしか出ないものがあります。
- 同じスクリーンショットに、バニラの同等品を並べて写してください。

## タッチ操作でのエンティティ（実機で確認済み、iOS 1.26.50）

- エンティティを**タップすると「攻撃」**になる。エンティティの「開く」は、画面の**「開く」ボタン**か**長押し**。チェスト付きトロッコと同じ挙動で、アドオンからは変えられない（クライアントの動作）。
- エンティティが覆っているブロックを「叩いて壊す」仕様なら、タップの連打で攻撃が入る（回数を数える）。クリエイティブで、1 回の攻撃で壊れる仕様にすると、**タップ 1 回で壊れる**。利用者には「開こうとして壊した」と感じられるので、README に書くか、確認ダイアログの代わりになる工夫を検討する。
- カーソルを当てたときに、エンティティの名前（`nameTag`、翻訳キー）が文字で出る（`block-definitions/` 参照）。

## 2 人でのテスト（VM をホスト、iPhone が LAN で参加。実機で確認済み）

- Mac 上の VM のネットワークを、`vmpal_update_vm` で `bridged`（Mac の主なインターフェース）にすると、VM が iPhone と同じ LAN のアドレスを持ち、**iPhone の「フレンド」の LAN の欄にワールドが出る**。共有（NAT）のままでは出ない。
- iPhone 側は、サーバーを選ぶと、**サインインが必要**だった（サインインなしでは入れない）。**別の Microsoft アカウント**を用意する（同じアカウントで 2 人にはなれない、と見られる。推測）。
- 詳細な手順は `device-testing-windows-vm/` を参照。
