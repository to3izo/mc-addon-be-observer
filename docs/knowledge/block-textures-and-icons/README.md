# ブロックのテクスチャとパックのアイコン

共有エンダーチェストで、スクリプトでテクスチャとアイコンを作り、バニラに見た目を寄せた経験のまとめです（iPhone と Windows 11 VM で見た目を確認）。

## テクスチャを「スクリプトで描く」やり方

- 64×64 の PNG を、Node.js だけで書き出すスクリプト（`assets/textures/generate_<名前>.mjs`）で作ると、ピクセルの規則と色を、あとから簡単に直せる（Blockbench を使わない）。依存パッケージは要らない（`zlib` で PNG を組み立てる。フィルタ 0 のRGBA8 で十分）。
- UV のレイアウトは、ブロックのジオメトリの箱の UV に合わせる（例: フタ [0,0] 14×5×14、本体 [0,19] 14×9×14、掛け金 [0,43] 2×4×1）。面ごとの位置を、スクリプトにコメントで残す。
- 確認の手順: 生成 → `pnpm build` → 開発用フォルダへコピー → ワールドに入り直す。**面ごとのコントラストは、実機でバニラの隣に並べて**比べる（昼の草原、空中、暗い部屋）。
- 比べるときのコツ: 上・横・底・正面の 4 方向のスクリーンショットを、バニラと並べて撮る。色の雰囲気が良くても、模様（縞の本数、暗い隙間の位置、底の格子）が違うと「別物」に見える。

## バニラの見た目に寄せるとき（Marketplace の注意）

- バニラのテクスチャのコピー、そこからの色替えは、Marketplace の審査で問題になるおそれがある（`marketplace/` 参照）。
- このプロジェクトでは、最初は自分の規則と乱数で描き起こしたが、「模様がバニラと違う」という指摘を受けて、owner が用意した、バニラの参考画像のデータを埋め込んだ色替えのスクリプトに置き換えた（ADR-0005）。**個人の配布なら owner の判断**だが、**提出前に、描き起こし版に戻すか、窓口に確認する**。描き起こし版は、git の履歴に残しておくと戻せる。
- 色は、スクリーンショットから測って、自分のパレットに置き換える（目の緑、アメジストの紫など）。ピクセルの形そのものを写し取ると、複製になる。

## ブロックの内側のテクスチャ（実機で確認済み、iOS）

- バニラのチェストは、フタの裏と本体の内側にもテクスチャがある。カスタムブロックで、フタを開く見た目を作るときは、**箱の内側の面**（フタの下面、本体の上面）にも絵を描く。単色のままだと、開いたときに目立つ。
- UV の「見えない面」（フタの下面、本体の上面）が、内側として見える。フタを開く角度の段階（`lid_0` 〜 `lid_4`）のどれでも、同じ UV を使う。

## パックのアイコン（`pack_icon.png`）

- 256×256 の PNG を、スクリプト（`assets/textures/generate_pack_icon.mjs`）で、ブロックのテクスチャから作った。ブロックの 3 つの箱を、**等角の投影**（光線を箱に当てて、最も近い面の色を取る）で描き、背景と粒子を足す。ビヘイビアパックとリソースパックに、同じ画像を書き出す。
- **向きを、ゲーム内のブロックのアイコンに合わせる**（このブロックは、正面が右、側面が左に見える向き）。逆向きだと、すぐ違和感に気づかれる。明るさは、上 > 左 > 右。
- 背景を変えずに中身だけ差し替えるときは、生成スクリプトの、ブロックを描く部分だけを変える。テクスチャを更新したら、アイコンも**必ず作り直す**（アイコンに目が写っている）。

## 色の測り方（スクリーンショットから）

- iPhone のスクリーンショット（webp）は、`sips -s format png` で PNG にして、Node.js の小さな PNG 読み込みで、画素の値を読む（`ffmpeg` でも切り抜ける）。
- 切り抜きは `ffmpeg -vf "crop=幅:高さ:x:y"`。`sips -c` は、オフセットの指定が効かず中央から切ることがある（`--cropOffset` を前に置いても結果は同じだった）。
