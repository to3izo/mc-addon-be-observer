# リリース前の整理と、紹介用のスクリーンショット

共有エンダーチェストをリリース候補にするときに行った作業と、実際に使った方法のまとめです。

## バージョンの付け方

- **メジャーは、公式マーケットプレイスに公開するまで 0 のまま**（公開時に 1.0.0）。仕様を変えたらマイナーを上げ、修正・見た目・文書・翻訳はパッチを上げる（`docs/adr/0007-versioning.md` の例）。
- 実機の確認用ビルドごとに、パッチ番号を上げる（iPhone は、UUID とバージョンが同じパックを取り込まない。`device-testing-ios/` 参照）。確認用ビルドの内容は、最初の公開版の CHANGELOG にまとめて書く。

## README に書くこと（利用者向け）

テンプレートの説明を、アドオンの説明に書き換える。次の順が読みやすかった。

1. 一言の説明、特徴（4〜5 個）、レシピ、使い方
2. **バニラとの違い**（隠さない）
3. **注意事項**（データが失われるリスクを含む）
4. 必要な環境と、確認した範囲、**未確認の範囲**（Android、コンソール、Realms など）
5. インストール方法、互換性、開発用コマンド

- 事実は、確認済みのことだけを書く。「バニラと同じ」「安全」のような断定は避ける。
- 「強制終了で、アイテムが消えたり増えたりすることがある」のような、設計上のリスクは、README、CHANGELOG の既知の問題、SPEC の制約に、同じ内容で書く。

## 紹介記事の依頼プロンプトの作り方

- 事実の一覧（確認済み）、注意事項（必ず書く）、書いてはいけない表現（未確認の断定、公式を思わせる表現）、構成案、出力形式（Markdown、末尾に「確認が必要な点」）を、1 つのプロンプトにする。
- 事実に書いていないことを書かせない、と明記する。未確認の機種（Switch、Android など）は、記事にも「未確認」と書かせる。

## 紹介用のスクリーンショット（Windows の VM、実機で確認済み）

- **HUD を消す**: `F1`。メッセージ（チャットの出力）は、数秒で消える。アクションバーも消える。
- **撮影は、ゲストの画面全体を保存する**のが確実（`vmpal_screenshot` は縮小される）。PowerShell で、`System.Windows.Forms` の `CopyFromScreen` で PNG に保存し、共有フォルダー（`Z:\Downloads\…`）へ書く。解像度は 1920×998 だった。
- **Windows ライセンス未認証の透かし**が、右下に写る。透かしは、Minecraft の動作と関係ない。認証すると消える。認証していない場合は、画像の下の 142 px（高さ 856 に）を切り落とす（`ffmpeg -vf crop=1920:856:0:0`）。切り抜いた版は `media/exports/`、元の画像は `media/source/screenshots/`（加工しない）。
- **構図**: `/tp @s x y z facing x y z` で、位置と向きを決める。`facing` を使っても、上下の向きが思ったとおりにならず、ほぼ水平になることがあった。`mouse_move` で微調整する（ゲームがマウスを掴んでいるときは、画面中心からの差分が視点の回転になる。回転量は画面上の移動の 2〜2.4 倍）。
- **ブロックの向き**: `setblock` で置いたカスタムブロックは、向きが `placement_direction` の既定になる。バニラのブロックは `["facing_direction"=3]`（南向き）のように、状態を指定して向ける。JIS 配列の日本語キーボードでは、`[` は `BracketRight`、`]` は `Backslash`、`@` は `BracketLeft`、`"` は `shift+2`、`=` は `shift+Minus`。
- **場面の作り方**: 平らな足場を `fill` で作り（`grass_block`、空中の高さ 199）、昼なら `time set 4000`、夜なら `time set 18000`、昼夜の切り替えを止めるなら `gamerule dodaylightcycle false`。暗い部屋で光源を見せるなら、`fill … deepslate_bricks hollow` で部屋を作る。**`hollow` は内側を空気に置き換える**ので、先に置いたブロックが消える。置くのは、箱を作ったあとにする。床の高さ（箱の最下段が床）にも注意する。
- **後片付け**: `fill … air replace <ブロック>` で、置いたブロックを種類ごとに消せる。
- **クラフトの場面**: 作業台を開き、材料を、スロットの座標に、クリックと右クリックで並べる（左クリックで持ち、右クリックで 1 個ずつ置く）。ホットバーの選択は、置いてしまわないように、空のスロットにしておく（置くつもりのないブロックを持ったまま壁を右クリックすると、そこに置かれる）。
- **インベントリの場面**: 中身が入ったチェストを開いて、マウスを UI の外へ動かしてから撮る（ツールチップが出ない）。

## 紹介用スクリーンショットの撮り方の補足（Windows の VM。2026-10-11〜12、実機で確認済み）

撮影の道具（F2 と HUD、透かしの避け方、画面の大きさ）は `device-testing-windows-vm/` を見てください。ここでは、見栄えのよい画像にするための工夫です。

- **足場は、補助パックの `.mcfunction` にまとめる。** 1 場面 = 1 関数（組み立て）と、カメラの位置の関数に分けると、やり直しが速い。1 つの関数が長くなっても動くが、1 行でも解析できないと関数全体が読み込まれない（`device-testing-windows-vm/` 参照）。ワールドを入り直すと、読み込み直される。
- **カメラは `/camera @s set minecraft:free pos x y z facing x y z` で置く。** プレイヤーが写らず、座標で構図を決められる。戻すときは `/camera @s clear`。カメラの近くにプレイヤーがいると、画面に写り込む（カメラの位置の手前にいると、頭が写った）。プレイヤーは、`/tp` で画角の外へ離しておく。
- **向きの取り違え:** 南（+z）を向くと、+x が画面の左になる。「左がバニラ、右が滑らか」のように並べ分けるときは、座標を反転して置く。1 枚撮るたびに画像で確かめる。
- **背景:**
  - 白いコンクリートは、透明ガラスや白のガラスが背景に溶けて見えなくなった。明るい灰色（`light_gray_concrete`）にすると、全色が映えた。
  - 水槽は、水色（`light_blue_concrete`）の背景にすると、魚と水が見やすい。暗い色の背景だと、魚が溶けた。
  - 板ガラスの背景を、板のすぐ後ろに置くと、斜めから見たときに、継ぎ目のような縦線が出て見えた（原因は推測。背景を 1 ブロック以上離すと目立たなくなった）。
  - 写り込みを避けるため、背景は、画角より広く、高く作る（上や端に空や雲が写る）。
- **スクリプトで状態を持つブロックは、`/fill` で置き直すと、状態が更新されないことがある。** 滑らかな板ガラスを `/fill` で別のブロックの上から置き換えたとき、腕のない柱だけになる板が出た。いったん `fill … air` で消してから置き直すと、正しくなった（プレイヤーの設置・破壊で状態を更新する作りのため。原因は推測）。
- **水槽の場面:**
  - 順序は「水槽の枠 → 水と砂 → サンゴ、昆布、海藻、シーピクルス → 魚」にして、うまくいった（植物を先に置いて水を `fill` で入れた場合の挙動は未確認）。
  - 熱帯魚は `/summon tropicalfish x y z`（`tropical_fish` ではない）。底に固まって小さく見えるので、数を増やし、水の上のほうに召喚する。`tp` で持ち上げた魚は消えた（原因は未確認）ので、最初から高さを指定して召喚する。
  - 召喚した魚は動き続けるので、撮影の直前に召喚する。数秒で位置が変わる。
- **UI の場面（石切台・作業台）:** `shift` + クリックで、材料をまとめて移せる。レシピのツールチップを写すときは、`mouse_move` のあとに 1 秒以上待つ。ホットバーの選択が、置いてしまうブロックにならないように注意する。
- **画像の保存:** 元の画像（F2 や `PrintWindow` で得たもの）は、そのまま `media/source/screenshots/` に、`<内容>_<yyyymmdd>.jpg|png` で置く。加工が要る場合は `media/exports/` へ。保存前に必ず画像を見て、HUD、プレイヤー、透かし、画面の端の空が写っていないことを確かめる。
