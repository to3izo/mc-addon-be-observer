# ADR（Architecture Decision Record）

「なぜそう決めたか」と「いつ何をしたか」を残す場所です。**ほかの文書（`docs/*.md`・`AGENTS.md`）は、いまの仕様と手順だけを、現在形で書きます。** 決定の理由・検討した案・日付つきの記録（確認した・設定した・切り替えた）は、ここに置きます。

手で直すことが多いため、ADR は日本語で書きます（ナレッジと同じ。`docs/knowledge/README.md` 参照）。ナレッジは「分かった事実と確認の方法」、ADR は「何をなぜ決めたか」です。

## いつ書くか

- 設計の選択をしたとき、ほかの案を採らなかったとき、制約や限界を受け入れたとき、`AGENTS.md` の規則の例外を認めたとき。
- コードや文書を読んでも理由が分からない決定を、したとき（あとで、決め直す前に読むため）。
- 作業を始める前に、触る領域の ADR を読む（`AGENTS.md` の「AI agent workflow」）。決定を覆す前に、理由を確かめる。

## 書き方

- 1 つの決定につき 1 ファイル: `NNNN-短い名前.md`。番号は連番で、決め直したときは、新しい ADR を足し、古いほうの状態を「置き換え済み」にする（古い ADR は消さない）。
- 短くてよい。**決定・理由・影響**が分かれば足りる。
- 日付つきの記録（「2026-10-03 に確認した」「設定した」など）は、その決定の ADR の「経過」に書く。いまの仕様の文書には書かない。
- 外部の事実の日付（料金の時点・測定日・今後の予定）は、データの出どころなので、各文書に残してよい。
- 一覧（下の表）に、1 行を足す。

## ひな形

```markdown
# ADR-NNNN: タイトル

- 状態: 採用 / 保留 / 置き換え済み（ADR-MMMM）
- 日付: YYYY-MM-DD（決定）
- 決定者: 運営

## 背景
なぜ決める必要があったか。

## 決定
何を決めたか。

## 理由・検討した案
なぜそれにしたか。ほかの案と、採らなかった理由。

## 影響
コード・文書・運用への影響。詳しい仕様の文書へのリンク。

## 経過
- YYYY-MM-DD: 起きたこと（確認・設定・切り替え・見直し）
```
