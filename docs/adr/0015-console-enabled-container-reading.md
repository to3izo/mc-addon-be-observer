# ADR-0015: コンテナーの中身の読み取りを足し、ON にできるのは BDS のコンソールだけにする（メモリだけに持つ）

- 状態: 採用
- 日付: 2026-10-19
- 決定者: 運営（利用者が方式を選び、計画を承認）

## 背景
アドオンを試す開発者（チェストのアドオンなど）と、AI エージェントのツールが、ブロックのインベントリ（チェスト・樽・ホッパー・かまど など）の中身を知りたい。ADR-0009 で後回しにし、「開けずに中身が見えるので、既定は OFF」とだけ決めていた。

ON にする方法が決まっていなかった。設定をワールドに保存すると、読み取り専用（ADR-0003）に反する。気にしたのは次の 2 つ。

- operator や AI ツールが、ほかのプレイヤーの拠点のチェストを開けずに見られる（プライバシー・公平さ）。
- AI のプレイヤーが「チェストの透視」をして、ずるい遊び方になる。

要求を送れるのは、BDS のコンソール、operator（チャット・カスタムコマンド）、コマンドブロック、ほかのパックのスクリプトだけで、一般の参加者（member）は送れない（ADR-0010）。BDS のコンソールを持つ人は、ワールドのファイルを直接読める。

## 決定
1. 新しいメソッド `container` を足す。引数は `x`・`y`・`z`・`dimension`（`block` と同じ）と `fromSlot`。
   - ブロックの `minecraft:inventory` コンポーネント（安定版 `@minecraft/server` 2.10.0 の `BlockInventoryComponent`）を読む。
   - `size`・`emptySlots`・`items`（使っているスロットだけ。`slot`・`typeId`・`amount`・`nameTag`）を返す。
   - ブロックの種類は限定しない。インベントリがないブロックは `container: null`。
2. 新しいメソッド `features` で、任意の機能を付け外しする。いまの機能は `containers` だけ。引数は `enable`・`disable`（`subscribe` と同じ形）。
3. **起動時は OFF。** 状態はメモリだけに持ち、ワールドには書かない。`/reload` と再起動で OFF に戻る。
4. **ON にできるのは BDS のコンソールだけ。**
   - コンソールとは、ゲームが送り主を「サーバー」と伝え（`/scriptevent` は `Server`、カスタムコマンドは `command:Server`）、送り主のプレイヤーがいない要求のこと。
   - ほかからの `enable` は `PERMISSION_DENIED`（新しいコード）にし、何も変えない。
   - パックのスクリプトの `runCommand` も、ゲームは「サーバー」と伝える。サーバーの持ち主が入れたコードなので、コンソールと同じ扱いにする。
5. **OFF には誰でもできる。** 止めるほうは安全なため。
6. **ON の間は、要求を送れる全員が読める。** 状態はサーバーに 1 つで、全員で共有する（`subscribe` と同じ）。
7. OFF のときの `container` は `FEATURE_DISABLED`（新しいコード）。
8. 読める範囲は、読み込み済みのチャンク。距離の制限は設けない。チャンクは読み込まない（`unloaded`）。
9. 大きさ:
   - 読むのは `maxInventorySlots`（54）まで。
   - `container.items` を切り詰めの対象にする（`truncated`・`omitted`）。
   - 切られたときに残りを取れるよう、`fromSlot` を足す。
   - アイテムの中のアイテム（チェストの中のシュルカーボックスの中身）は読まない。
10. `capabilities` に `optionalFeatures: { kinds, enabled }` を足す。
11. どれも互換な追加なので、`protocol` は 1 のまま、MINOR を上げる（ADR-0013）。

## 理由・検討した案

| 案 | 判断 | 理由 |
| --- | --- | --- |
| (a) 常に ON | 採らない | 「既定は OFF」（ADR-0009）に反する。AI ツールが何もしなくても透視できる |
| (b) 要求で ON（`subscribe` と同じ） | 一部を採る | ワールドに書かずに済む。ただし operator なら誰でも ON にでき、今の「送れる人」と変わらない |
| (c) ON にできるのはコンソールだけ | **(b) と組み合わせて採る** | 決めるのが「ワールドのファイルを読める人」なので、新しく見える範囲が増えない。主な使い手（VM の AI ツール）は、もともとコンソールから送っている |
| (c') コンソールからの要求だけが読める（切り替えなし） | 採らない | 既定 OFF にならない。チャットで試す開発者が使えない |
| (d) operator だけ | 採らない | すでに今の状態で、新しく防げるものがない |
| (e) サーバーの設定ファイル（`@minecraft/server-admin` の `variables`） | 採れない | npm の版がすべて `1.0.0-beta.*` で、安定版がない（2026-10-19 に `npm view` で確認）。ADR-0001 に反する |
| (f) ビルド時のフラグ（別のビルド） | 採らない | 配る物が 2 種類になる。AI ツールの利用者が自分でビルドすることになる |
| (g) 運営が作るスコアボードの目標を目印にする | 採らない | ワールドに残る。チートが ON なら、チャットの operator も作れる |
| `Owner` 権限の専用コマンドで切り替える | 採らない | `CommandPermissionLevel.Owner` はコンソールだけに絞れるが、入口が 1 つ増え、足すたびにサーバーの再起動が要る。送り主の種類で見分ければ足りる |
| ON の間も、読めるのはコンソールだけ | 採らない | チャットで確かめる開発者が使えない。operator はもともと全員の持ち物（インベントリ）を見られる |
| プレイヤーの近く（例: 8 ブロック）だけ読める | 採らない | ON にできるのがコンソールだけなら、効果が小さい。コンソールからの要求には、基準になるプレイヤーがいない |
| 種類を限定する（チェストだけ、など） | 採らない | ゲームが持つインベントリをそのまま読むほうが単純で、新しいブロックにも対応する |
| `fromSlot` なしで切り詰めだけ | 採らない | 試験で、長い ID（43 文字）で埋めた大きいチェストが 1 行に収まらないと分かった。protocol 1 にはページングがないので、残りを取る方法が要る |

## 影響
- `docs/PROTOCOL.md` §5.1、§5.15 `features`、§5.16 `container`、§6（`PERMISSION_DENIED`・`FEATURE_DISABLED`）、§7（`container.items`）
- `docs/SPEC.md`（18）、`docs/CONTENT.md`、`SECURITY.md`（ON の間は、要求を送れる全員が中身を見られる）、README
- `docs/TESTING.md`: U-PROTO-18〜20、OBS-CON-01〜10
- 確認用のケース: `docs/knowledge/bds-local-server/scripts/bo-verify-container-cases.json`
- ゲームの動き: `docs/knowledge/bds-local-server/` の「コンテナーの読み取り」
- 読み取り専用の性質は変わらない。アドオンが持つ状態は、メモリの中だけ（最近のイベント、追加のイベントの ON/OFF、機能の ON/OFF）。

## 経過
- 2026-10-19: 利用者が、(b)＋(c)（コンソールだけが ON）、ON の間は送れる全員が読める、範囲は読み込み済みのチャンク、を選んだ。計画を承認した。コミットは main に直接置く、と指示された。
- 2026-10-19: 実装し、BDS 1.26.52.3 で確認した。単体テスト 86 件、OBS-CON-01〜09、確認用のケース 21/21、回帰 34/34、追加のイベントのケース 21/21（`docs/TESTING.md`）。OBS-CON-10（ルートテーブル）は未実施。
  - 試験で分かり、計画に足したこと:
    - 長い ID で埋めた大きいチェストが 1 行に収まらなかったので、`fromSlot` を足した
  - 試験で分かったゲームの動き:
    - 大きいチェストは、どちらの半分も 54 スロットの同じインベントリを返す
    - クラフター・エンダーチェスト・模様入りの本棚・飾り壺・焚き火は、Script API にインベントリが出ない
- 2026-10-19: 未確認だった OBS-CON-10 を確認した。利用者の許可を得て、`server.properties` を一時的に新しいワールド（`level-name=addon-lab-loot`、`level-type` をコメントアウト）に切り替え、開けていない宝のチェスト（埋もれた宝）を読んだ。2 回とも空（`emptySlots` 27）で、そのあとクライアントで開けると中身（27 スロット）が生成された。読むことでワールドは変わらないので、決定はそのままにした。ルートテーブルが残ったチェストは空に見えることを、`docs/PROTOCOL.md` §5.16 に書いた。`server.properties` は元に戻した。
